# 部署與使用說明

## 0. 先決定：用哪個帳號部署

網頁應用程式以「部署者」身分讀寫試算表。建議用**組織的公用 Google 帳號**（公會信箱）部署，
不要用個人帳號；否則負責的人交接或離開後，網頁會停擺、得重新部署（網址也會變）。

試算表的擁有者最好也是同一個帳號。

## 1. 建立 Apps Script 專案

### 做法 A：編輯器貼上（不需要安裝任何東西）

1. 用上面決定的帳號登入，開 <https://script.google.com> → 新增專案。
2. 左側預設的 `程式碼.gs` 改名為 `Code`，內容全部換成 `src/Code.gs`。
3. 「＋」→ 指令碼，命名 `Config`，貼上 `src/Config.example.gs` 的內容（下一節會改）。
4. 「＋」→ HTML，命名 `Index`（不要打 `.html`，大小寫要一致），把預設內容全部刪掉再貼上 `src/Index.html`。
5. 專案設定 → 勾「在編輯器中顯示 appsscript.json 資訊清單檔案」→ 把 `src/appsscript.json` 貼進去
   （時區與網頁應用程式存取權都在裡面）。

### 做法 B：clasp（會用終端機的人）

```
npm i -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json     # 填 Script ID（專案設定 → ID）
cp src/Config.example.gs src/Config.gs
clasp push
```

`.claspignore` 只放行 4 個檔案，其他文件不會被推上去。

## 2. 改 Config.gs

至少改這幾項：`ADMIN_NAMES`、`STAFF_ACCOUNTS`、`UI` 整段、`SETUP_ROSTER`（第一次建表用）。
逐欄說明見 [customize.md](customize.md)。

## 3. 建立試算表結構

### 從零開始

1. `SPREADSHEET_ID` 留空白。
2. 編輯器上方函式選 `setupSpreadsheet` → 執行。第一次會要求授權：選同一個帳號 →
   「Google 尚未驗證這個應用程式」→ 進階 → 前往（不安全）→ 允許。這是自己寫給自己用的腳本，正常現象。
3. 看「執行記錄」：會印出新試算表的網址與 ID。把 ID 填進 `Config.gs` 的 `SPREADSHEET_ID`，儲存。
4. 再執行一次 `setupSpreadsheet`：建好次月的月份分頁（順位名單取 `SETUP_ROSTER`）與隱藏的 `_可排班日`、`_操作紀錄`。

### 已經有試算表

填 `SPREADSHEET_ID`，執行 `diagnose` 看程式認不認得你的分頁。版面要求見 [architecture.md](architecture.md#試算表版面契約)。

## 4. 部署成網頁應用程式

1. 右上角 **部署 → 新增部署作業**。
2. 類型：**網頁應用程式**。說明隨意（例：`排班 v3.9`）。
3. **執行身分：我**。**具有存取權的使用者：知道連結的任何人**。
4. 部署 → 複製 `https://script.google.com/macros/s/.../exec` 網址。

之後改程式：**部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新增版本」→ 部署**，網址不變。
clasp 的話：`clasp push` → `clasp create-version "說明"` → `clasp redeploy <部署 ID> -V <版本號>`。
**不要**用 `clasp create-deployment` 或「新增部署作業」做改版，那會產生新網址。

Apps Script 對已部署頁面有快取，改版後用瀏覽器驗證要在網址後加 `?cb=123` 之類的參數。

## 5. 帳號怎麼運作

| 項目 | 說明 |
|---|---|
| 初始密碼 | 全部是 `DEFAULT_PASSWORD`（預設 `0000`） |
| 改密碼 | 登入後右上「設定」；4～6 位數字，不能還是預設值 |
| 忘記密碼 | 查不回來（只存雜湊）。後臺 → 使用者密碼重設 |
| 記住登入 | 30 天；按「登出」立即失效 |
| 誰還沒改 | 後臺 → 使用者密碼重設 → 看誰還沒改密碼 |
| 登入鎖定 | 連錯 10 次鎖 10 分鐘；替他重設密碼會一併解鎖 |
| 會務人員帳號 | `STAFF_ACCOUNTS`；能看不能填；後臺功能由超級管理者授權 |

⚠️ 在大家改密碼之前，預設密碼是共用的。公告時一定要寫「請立刻改密碼」。

## 6. 後臺管理

只有超級管理者（`ADMIN_NAMES`，範本預設是「會務人員」帳號）與被授權的人看得到，各分項依權限顯示：

| 分項 | 做什麼 | 權限鍵 |
|---|---|---|
| 班表鎖定 | 定案後鎖住該月；所有人仍可查閱，到該月 1 號自動解除 | `lock` |
| 編輯注意事項 | 寫進該月分頁的注意事項欄 | `notes` |
| 標記逾期放棄 | 把逾期未填的人標完成，順位往下 | `skip` |
| 建立月份分頁 | 只建下一個月，或一路建到某年某月；順位逐月遞補 | `create` |
| 編輯開放日 | 月曆格子變切換鈕，`X ↔ 開放`，早晚班各自獨立 | `openday` |
| 使用者密碼重設 | 打回預設密碼；看誰還沒改 | `resetpw` |
| 增減人員 | 新人加在順位最後（代號接續）；移除會從本月起所有分頁拿掉，有班的要先取消 | `roster` |
| 頁首頁尾文字 | 改頁首標題（電腦版／手機版分開）、登入頁說明、頁尾文字，不必重新部署 | `brand` |
| 權限授權 | 超級管理者逐項勾選開放給誰（含會務人員） | 只有超級管理者 |
| （代管班表） | 取消他人的班、代交棒、鎖定期間仍可改 | `manage` |

## 7. 每月流程

| 時間 | 誰 | 動作 |
|---|---|---|
| 公布日（`OPEN_DAY`） | 管理者 | 後臺 → 建立月份分頁；確認可排班日（週日自動開，其餘用「編輯開放日」）；填注意事項 |
| 公布日起 | 成員 | 依順位填班；填完（或不排）按「換下一位」 |
| 逾期 | 管理者 | 後臺 → 標記逾期放棄 |
| 期限（`DEADLINE_DAY`） | 全體 | 完成；管理者視需要鎖定 |

「換下一位」是整套順位的樞紐：系統用「完成註記」判斷輪到誰，**不排班的人也一定要按**。

## 上線檢查清單

- [ ] 手機開部署網址，看得到月曆與順位面板
- [ ] 頁尾版本正確；頁首、規則、聯絡方式是你們的（來自 `Config.gs`）
- [ ] 登入下拉有全部成員（遮罩姓名）與會務人員帳號
- [ ] 用預設密碼登入、改密碼、登出、用新密碼再登入
- [ ] 點一格 → 名字出現 → **回試算表看那一格真的寫進去了** → 按「復原」→ 試算表那格變空白
- [ ] 連填兩班，第二次跳「超過每月班數」警示
- [ ] 按「換下一位」→ 試算表完成註記變 TRUE → 下一位變橘色
- [ ] 手機與電腦同時開，手機填一班，電腦 60 秒內自動出現
- [ ] 超級管理者看得到全部 9 個後臺分項；一般成員完全看不到後臺
- [ ] 已替超級管理者（會務人員）帳號改掉預設密碼
- [ ] 會務人員登入：能看、不能填；授權一項後只出現那一項
- [ ] `_操作紀錄`（檢視 → 隱藏的工作表）有剛才的動作
- [ ] 把測試資料清乾淨，再公告
